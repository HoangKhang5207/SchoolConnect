## 2. Comprehensive Risk Register (`RSK-001` to `RSK-010`)

Every identified risk across **Technical**, **Operational**, **Security**, **Business**, and **Schedule** domains is tracked below with its Probability, Impact, Mitigation, Owner, Trigger, and Contingency plan.

| Risk ID | Category | Description | Probability | Impact | Proactive Mitigation | Owner | Early Warning Trigger | Contingency Plan (If Triggered) |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| **`RSK-001`** | **Platform / Operational** | **Zalo Testing Access Restriction:** TitKul Director cannot open the Zalo Testing QR on their personal phone if their Zalo account is not added to the Mini App's Developer/Admin group (`CF-07`). | Medium | High | Design dual demo delivery (`Option A`: invite Director's Zalo account to Developer role; `Option B`: live mobile/Zalo Studio screen projection + public HTTPS web preview in `DEMO_MODE`). | Project Owner (`Hoàng Khang`) | Director prefers not to share Zalo phone/ID before the 15:00 meeting or Zalo permission invite is delayed. | Immediately run the interactive demo via live screen share + mobile responsive web URL (`DEMO_MODE`) where the Director can click and test every flow directly without Zalo whitelist restrictions. |
| **`RSK-002`** | **Technical** | **CORS & HTTPS Blocking in Zalo WebView:** Zalo Mini App runs on `https://h5.zdn.vn` and rejects plain `http://` Backend calls or fails on `OPTIONS` preflight requests (`CF-08`). | Medium | Critical | Configure Spring Security `CorsConfigurationSource` in `M1` to explicitly allow `https://h5.zdn.vn`, `http://localhost:*`, and tunnel domains with `OPTIONS` support (`AC-018`). | Tech Lead / AI Assistant | Browser console or Zalo DevTools logs `CORS policy: No 'Access-Control-Allow-Origin'` or `Mixed Content` error. | Verify `OPTIONS /api/v1/health` with `Origin: https://h5.zdn.vn` via automated test in `M1`; expose Backend via HTTPS tunnel (`Cloudflare Tunnel` / `ngrok`) or Cloud PaaS with TLS. |
| **`RSK-003`** | **Platform / Security** | **Zalo Enterprise App ID / SDK Permission Gate:** Personal Zalo Developer accounts cannot invoke restricted enterprise APIs (like `getPhoneNumber`) without business verification (`OQ-04`). | High | Medium | Implement **Dual Auth (`DEMO_MODE` + `ZALO_AUTH`)**: default to `DEMO_MODE` with pre-seeded Parent (`Trần Thu Hà`) and Teacher (`Cô Lê Thanh Thảo`) profiles while keeping `ZALO_AUTH` (`getAccessToken` + `appsecret_proof`) configurable via env vars. | Tech Lead / AI Assistant | `getAccessToken()` returns error in browser or unbound Mini App environment. | Auth service automatically catches SDK error and falls back seamlessly to `DEMO_MODE` in `< 500ms` so the user journey never breaks. |
| **`RSK-004`** | **Business / Design** | **Visual Imitation of Reference Screenshots:** UI layout accidentally resembles one of the 5 uploaded reference screenshots (`SRC-002` to `SRC-006`), violating `CF-05` (`Tuyệt đối không được bắt chước giống`). | Low | Critical | Design a bespoke **SchoolConnect Design System** (warm emerald/teal & soft cream educational theme, unified child switcher header, timeline cards, and split Parent/Teacher switcher) completely distinct from `SRC-004`'s 3x3 icon grid or `SRC-002`'s orange e-commerce theme. | Frontend Lead / AI Assistant | Any screen layout visually mirrors the 3-column icon grid of `SRC-004` or banners of `SRC-002`/`SRC-005`. | Refactor screen layout immediately during `M1`/`M2` UI review to use clean modern card sections and segmented tabs instead of icon grids. |
| **`RSK-005`** | **Schedule** | **24-Hour Compressed Timeline Pressure:** With the live demo at **15:00 tomorrow (2026-11-05)** (`OQ-03`), attempting to build non-essential features could delay testing and rehearsal. | Medium | High | Strict adherence to **Vertical Slice execution (`M1` -> `M4`)** and **MoSCoW boundaries**. Lock all `Must Have` flows by `05/11 10:00` and reserve `13:30 – 15:00` exclusively for final verification and rehearsal. | Project Manager / Owner | Any sprint exceeds its time-box by more than 45 minutes. | Drop `Could Have` polish items (such as client-side announcement search `FE-SEARCH`) to protect `M3` (Closed-Loop Leave Request) and `M4` (Testing & Deployment). |
| **`RSK-006`** | **Technical / Build** | **Local Database or Port Conflict:** Local PostgreSQL (`port 5432`) or Backend (`port 8080`) conflicts with an existing service on the Windows workstation. | Medium | Medium | Configure parameterized ports (`SERVER_PORT`, `DB_PORT`) in `application.yml` and `docker-compose.yml` with clear health checks. | DevOps / AI Assistant | `Port 8080/5432 was already in use` on Spring Boot or Docker startup. | Inspect active ports before startup, bind to existing local PostgreSQL 17 instance or use mapped Docker port (e.g., `5433:5432`), and verify via `/api/v1/health`. |
| **`RSK-007`** | **Technical / Domain** | **Timezone Mismatch on Leave Request Dates:** Client browser sends UTC date while Backend compares against system timezone, falsely rejecting a valid "Today" leave request (`RULE-002`). | Low-Med | Medium | Standardize Backend clock and date validation explicitly on `ZoneId.of("Asia/Ho_Chi_Minh")` (`GMT+7`). | Backend Lead / AI Assistant | Submitting a leave request starting `today` fails `startDate >= today` validation early in the morning. | Force `Asia/Ho_Chi_Minh` timezone in Spring Boot `JacksonConfig`, JPA settings, and `LeaveRequestService` date validators, covered by unit tests. |
| **`RSK-008`** | **Operational** | **Network / Tunnel Instability During Live 15:00 Demo:** Public Wi-Fi or HTTPS tunnel drops during the live presentation with the TitKul Director. | Low-Med | High | Keep a complete **Local Full-Stack Loop** (`localhost` Frontend + `localhost:8080` Backend + local PostgreSQL) running on the presentation laptop AND record a high-resolution **Backup Demo Video** in `M4`. | Project Owner (`Hoàng Khang`) | Remote tunnel latency exceeds `2000ms` or disconnects prior to the 15:00 meeting. | Switch immediately to the local `localhost` mobile simulator + Swagger UI + DBeaver/psql on screen share, and provide the recorded Demo Video as supplemental evidence. |
| **`RSK-009`** | **Security** | **Cross-Student Data Leak (IDOR Vulnerability):** A parent modifies `studentId` in the URL/API payload to view another child's records (`RULE-001`). | Low | Critical | Enforce `GuardianAccessService.verifyParentOwnsStudent(parentId, studentId)` in the `service/` layer before every student query or mutation, verified by automated test `AC-006`. | Security / Backend Lead | Any `/api/v1/children/{id}/...` endpoint queries `StudentRepository` without checking `parent_students`. | Block in code review and verify via automated `JUnit` integration test asserting `HTTP 403 Forbidden` for unlinked `studentId`. |
| **`RSK-010`** | **Security / Compliance** | **Accidental Exposure of Secrets or Real PII:** Committing API keys, JWT secrets, or real student data into the Git repository (`CF-06`, `NFR-005`). | Very Low | Critical | Use `.env.example` and environment variable placeholders (`${JWT_SECRET:...}`) in `application.yml`; populate `seed.sql` strictly with fictional personas (*Trường Mầm Non Sao Mai*, *Nguyễn Minh An*, *Nguyễn Minh Khôi*). | Tech Lead / AI Assistant | `.env` file or real credentials appear in `git status`. | Enforce strict `.gitignore` rules before the very first `git add` in `M1`. |
